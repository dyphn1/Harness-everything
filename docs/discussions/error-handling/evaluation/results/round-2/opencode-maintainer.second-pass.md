## identifier / name / status responsibilities (from nodes.yaml + README)

- **`identifier`** (`ERR-YYYYMMDD-UUIDv4`): the persistent identity of an Action. Immutable once accepted; category and date are descriptive only, UUIDv4 supplies collision resistance. It is the only proposed persistent identity; the drawings' A–G aliases and node ids explicitly are *not* identities. My first-pass statement that A–G are drawing-local is confirmed.
- **`name`**: the human/agent-readable meaning ("Capture", "Triage", … "Accept and retire"). It is what the diagrams display instead of UUIDs, and it "can change independently" of the identifier — so a rename changes `name` and the rendered labels, never `identifier`.
- **`status`**: separate metadata, currently `proposed` for all seven Actions in this discussion draft. The README states no lifecycle transition specification is locked yet — so status carries draft state, not behavioural state, and is unrelated to the UNVERIFIED step-status in View 1 (that is a work-item status, not an Action status — the README never connects them).

All seven Actions in nodes.yaml match the seven Actions the diagrams show, one-to-one, with the same names.
