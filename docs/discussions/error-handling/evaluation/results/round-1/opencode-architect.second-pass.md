## Differences and corrections

1. **I inverted the view numbering.** In my first pass I called Diagram 1 the "View 2 (expanded) rendering" and Diagram 2 "View 1 composed", reading the subgraph annotations (`ASSESS · View 2 composition`, `same block in View 1`) as if they named the diagram they appear in. My substantive relationship reading (branchy expansion vs composition-with-actors vs D drill-down) was correct; the numeric labels were swapped. The mapping table in `first-pass.md` should be re-read with columns "View 1 = Diagram 1", "View 2 = Diagram 2".
2. **Recurrence: the two loops are two distinct, intentional loops — my ambiguity resolves to the "two loops" reading.** I had written "same loop at different zoom (best guess) or two different loops (also defensible)". README: "An unrelated new problem re-enters at Capture, while a recognized recurrence may resume review of the existing disposition" and for G: "A later observation may trigger re-evaluation. This is conceptual return flow, not an automatic additional PR review round." So View 1's `RETIRE -.-> D` (recognized same-class recurrence → re-evaluate existing disposition) and View 2's `G -.-> INPUT → A` (new/unrelated observation → full re-capture) are both correct and deliberately different. The diagrams alone do carry the distinction weakly ("Later recurrence of same class" vs "newly observed recurrence"), but only the README states it as a rule; my readability flag remains valid.
3. **"Budget" is partially defined — my "undefined term" note is only half-true.** README: "The existing #437 budget suggestion is one correction plus one review; there is no global recurrence counter or forced Zoom-out." "Bounded review" remains without an independent definition beyond this (the bounded retry cap "max 3" is separate).
4. **`#359` and `#394` resolved: they are issue references to *existing* established mechanisms** ("Existing Error Ledger #359 and bounded context delivery #394 remain the established mechanisms; no new implementations are implied").
